Module 6 uses difflib.SequenceMatcher for fuzzy title matching — a real, working, dependency-light choice, and explicitly not the only or most sophisticated option. Here's the landscape it sits in.

02Beyond Character-Level Comparison

All of Module 6's matching operates on characters. Real large-scale deduplication systems often move up a level:

  • TF-IDF + cosine similarity — represents each title as a vector of weighted word-importance scores, then measures the angle between two titles' vectors. Catches word-order-independent similarity ("Fuzzing Directed by Control Flow" vs "Control-Flow-Directed Fuzzing") that character-level matching would score lower.
  • Embedding-based / semantic similarity — a modern approach using a trained language model to represent each title's meaning as a vector, catching genuine paraphrases with almost no shared vocabulary at all. This is powerful and increasingly common in real bibliographic deduplication tools, and explicitly out of this course's scope — see the ROADMAP's stated boundary against ML-based classifiers.

03The Scaling Problem Module 6 Doesn't Solve: Blocking

Module 6's Pass 2 is O(n²) — every surviving record compared against every other. Fine for the handful of records in this course's demos; genuinely unworkable for a real systematic review screening tens of thousands of records, where n² becomes hundreds of millions of comparisons.

Real large-scale deduplication systems (library catalogs, patent offices, national bibliographic databases) solve this with blocking: group records into buckets by some cheap key first (e.g. first three words of a normalized title, or publication year + first author's last name), and only run expensive fuzzy comparison within each bucket. Two records that could never plausibly be duplicates (wildly different titles, different decades) never get compared at all. This is the same "cheap check first, expensive check only when needed" discipline Module 6's two-pass design already uses — blocking is that same idea, one level further, applied to make the expensive pass itself tractable at scale.

04Real Systems Doing This Today

  • OCLC WorldCat clusters millions of library catalog records into FRBR "works" using a mix of exact identifier matching and title/author heuristics not unlike a much larger-scale version of Module 6's approach.
  • Crossref itself runs deduplication and similarity-checking as part of accepting new DOI registrations from publishers.
  • Reference managers (Zotero, EndNote) ship built-in "find duplicates" tools using DOI-first, fuzzy-title-second logic — the exact two-pass shape Module 6 implements, in production software researchers use daily.
