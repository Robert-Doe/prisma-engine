Concept Cluster 01Deduplication & Identity Matching

This isn't one module's topic — it's a question that recurs throughout the entire course: are these two things actually the same thing? Every time the answer matters, a different module had to answer it a little differently, and comparing those answers side by side reveals more than any single module's code motivates on its own.

01The Big Analogy

Every kind of ID check, in one lineup A passport check at a border is exact and unambiguous — the number either matches the database or it doesn't. A witness picking a suspect out of a lineup is comparing faces, which is fuzzier, needs a confidence threshold, and can be wrong in both directions. A detective noticing two unrelated case files both mention the same address is a third kind of match entirely — not identity, but connection. This course used all three, in different modules, for different reasons, and never named them as the same underlying problem until now.

03The Pattern Underneath All of Them

         Both share one discipline: NEVER apply the expensive/uncertain
         method to something the cheap/certain method could already decide.
         Module 6's two-pass ordering is the general shape; every reuse
         of normalize_doi() elsewhere in the course is really reapplying
         "prefer the cheap, certain check first" to a new situation.

04Why This Lives Here, Not Inside One Module

No single module owns this idea. Module 6 is where the fullest version of it (exact + fuzzy, two-pass) was built, but Module 3 sidesteps the whole problem for one specific case (format normalization), Modules 13/23/26 each reuse one small piece of Module 6 in a genuinely new context, and Module 25's gap is only visible by comparing it against the others. Reading only Module 6's tutorial would miss the pattern entirely; reading only Module 25's would miss that it's even a gap.
