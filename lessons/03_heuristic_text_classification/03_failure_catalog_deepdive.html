Concept Cluster 03 — Deep Dive 2The Full Heuristic-Failure Catalog

Every row below is a real, run, documented event during this course's own construction — not a hypothetical "here's what could go wrong." Collected in one place, a pattern emerges that no single module's own DECISIONS.md can show on its own.

ModuleHeuristicWhat actually happenedResolution
Module 1 suggest_framework_verbose() A question matching both a SPIDER and a PEO marker always resolves to SPIDER — checked first, by design, not a bug, but an ordering dependency worth knowing about Documented as a deliberate convention in DECISIONS.md, not treated as an error state
Module 9 design_is_comparative() Named directly in the tutorial's Limits section as capable of wrongly excluding a real comparative study that happens to use none of the three marker phrases — not triggered in the demo, but explicitly anticipated Left as a stated, un-fixed limitation — the point being made is that heuristics have describable failure boundaries, not that every one must be eliminated
Module 21 mentions_remote_work() The module's own first-draft demo text ("Unrelated to remote work practices") accidentally contained its own trigger phrase, self-sabotaging the intended "correctly excluded" example Demo text rewritten to avoid the accidental self-trigger — a real instance of an author's own test data tripping the exact heuristic being tested
Module 24 _is_negated() Two genuinely agreeing excerpts about social isolation were misclassified as "refutational," because one contained grammatical negation ("don't talk to") describing the phenomenon itself, not negating a claim about it Deliberately kept in the published module, explained directly in both the code's printed output and the tutorial, as the clearest real demonstration in the course of this exact failure class
Module 27 / Module 28 classify_approach() / extract_dimensions() Module 28's self-check used the phrase "without machine learning," which matched the substring "machine learning" regardless of the negation, marking a non-ML paper as ML-based Self-check example text rewritten to avoid the collision; the recurrence is documented in Module 28's DECISIONS.md as the same root cause as Module 24's, found independently
Module 30 An early, unshipped "contested theme" detector A positive/negative keyword heuristic (same style as Module 24's) was tried during development to detect themes where sources disagree — run against the module's own real demo data, it found zero contested themes, because the real disagreement in that data was across themes, a pattern the within-theme heuristic was never built to see Removed before shipping, rather than kept despite producing no useful signal on real data — documented in DECISIONS.md as a design decision made after testing, not assumed from the start

01What the Catalog Shows That No Single Row Does

  • Two independent negation-blindness failures (Modules 24 and 27/28) confirm this is a structural risk of substring-based classification generally, not a quirk of one word list
  • One heuristic was kept despite a known failure (Module 24, because the failure itself is the lesson) and one was removed because of a demonstrated failure (Module 30's contested-theme detector) — two different, both legitimate responses depending on whether the failure teaches something or just doesn't work
  • Every single row was caught by actually running real code against real or realistic data, never by inspection alone — consistent with this course's stated quality bar throughout both tracks
