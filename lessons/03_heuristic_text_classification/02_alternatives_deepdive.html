01NegEx: A Real, Purpose-Built Solution to This Exact Problem

The specific failure this cluster documents — confusing "negation describing a phenomenon" with "negation of a claim" — has a real, well-known name in clinical NLP research: distinguishing an asserted finding from a negated one in free text. NegEx (Chapman et al., 2001) is a real, widely-cited algorithm built specifically for this: it uses a curated list of negation trigger phrases and a defined scope window (how many words after a trigger the negation is considered to apply), so "no evidence of infection" correctly negates "infection" while "no evidence of infection, but severe pain" correctly stops the negation scope before "pain." This course's _is_negated() functions (Modules 24, 27) have no scope concept at all — presence anywhere in the text is treated as negating the entire excerpt, which is exactly the simplification that caused both real bugs this cluster documents.

02Dependency Parsing

Modern NLP libraries (spaCy, Stanford CoreNLP) can parse a sentence's grammatical structure and identify exactly which word a negation ("not," "n't") grammatically modifies — distinguishing "I do not think this works" (negates "think") from "I think this does not work" (negates "work") even though both contain the same negation token. This is a real, working solution to the scope problem NegEx approximates with simpler rules — at the cost of a genuinely heavier dependency (a full parsing library, model downloads, meaningfully more compute per sentence) than this course's stated architecture target permits.

03Modern LLM-Based Classification

A large language model, prompted directly ("does this excerpt describe agreement or disagreement with X"), can correctly handle negation-in-context essentially by default, because it's reasoning over meaning rather than matching substrings. This is a real, increasingly common approach to exactly the classification tasks Modules 1, 8, 9, 15, 21, 24, 27, and 28 all perform with keyword heuristics instead.

04Why This Course Used Keyword Heuristics Anyway

What keyword heuristics give up

  • Correctness on negation, sarcasm, context-dependent meaning — the entire class of failure this cluster documents
  • Any real semantic understanding — they match text shape, not meaning

What they buy instead

  • Zero external dependencies — every heuristic in this course runs on the Python standard library alone, matching the ROADMAP's stated architecture target
  • Total transparency — every classification decision traces to one visible, readable line of code, which is exactly why this cluster's own failures were discoverable and explainable at all
  • Deterministic, reproducible output — the same input always produces the same classification, with no model version or randomness to account for
The real tradeoff, stated plainly: this course chose auditability over accuracy, every time, on purpose. A production system doing this work for real should very likely reach for NegEx- style scoped negation detection or a proper NLP library at minimum — but a teaching module whose whole point is showing you exactly why a classification happened benefits from every decision being one grep-able line, even when that line is sometimes wrong.
