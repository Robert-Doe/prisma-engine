Prerequisite 3 of 9Bibliographic Metadata & Identifiers

The Big Analogy A URL is a street address that assumes the building never moves — example.com/paper breaks the day the site is redesigned. A DOI is more like a postal forwarding service: no matter how many times the publisher moves the actual file, doi.org/10.x/y always resolves to wherever it currently lives. That permanence is why every bibliographic system is built around DOIs as the primary key, not URLs.

01What's actually in a bibliographic record

Regardless of source, a citation record is a bundle of fields: title, author list, publication year, venue (journal/conference name), abstract, and one or more identifiers. Different systems expose different subsets and spell the field names differently — which is exactly the problem normalization solves.

02DOI — Digital Object Identifier

A permanent, globally unique string assigned by a registration agency (e.g. Crossref) at publication time. Format: 10.<registrant>/<suffix>, e.g. 10.1145/3243734.3243804. Resolvable at https://doi.org/10.1145/3243734.3243804. Because it's assigned once and never reassigned, it's the closest thing academic publishing has to a stable primary key — which is why deduplication (Module 6) treats a DOI match as decisive.

03RIS format

A plain-text, tag-based export format (used by EndNote, Zotero, and most databases). Each line is a two-letter tag plus a value:

TY  - JOUR
AU  - Smith, Jane
TI  - Remote Work and Productivity
PY  - 2023
JO  - Journal of Applied Psychology
DO  - 10.1037/xyz
ER  -

04BibTeX format

A LaTeX-oriented format, keyed by a citation key you choose:

@article{smith2023remote,
  title   = {Remote Work and Productivity},
  author  = {Smith, Jane},
  year    = {2023},
  journal = {Journal of Applied Psychology},
  doi     = {10.1037/xyz}
}

05Why this matters mechanically

RIS, BibTeX, and every academic API's JSON response name and structure the same underlying facts differently — RIS calls the title TI, BibTeX calls it title, Crossref's API calls it title as a list. A pipeline that has to handle multiple sources needs exactly one canonical internal shape that all of these get converted into on the way in.
