00Before You Start

Read Prerequisite 6 first — this module implements exactly the OR, RR, and SMD formulas it introduces, plus the confidence-interval logic.

01The Big Analogy

A ruler that stretches unevenly near zero Try to measure "how much bigger" with an ordinary ruler on a ratio like odds or risk, and the ruler misbehaves: a ratio can't go below zero, but it can go arbitrarily high above 1, so a margin of error computed directly on that ruler can come out lopsided — or, worse, with a lower bound below zero, which is nonsense for something that can never be negative.

The fix real statisticians use is switching to a logarithmic ruler, where the distances even out and become symmetric — compute the margin of error there, then convert back. odds_ratio() and risk_ratio() both do exactly this: work in math.log() space, then math.exp() the interval's endpoints back at the very end. standardized_mean_difference() never needs this trick — a difference, unlike a ratio, is naturally symmetric around zero already.

02What Happens, Step by Step

  1. For a binary outcome from a 2×2 table, odds_ratio() or risk_ratio() computes the point estimate directly, then its standard error on the log scale
  2. The confidence interval is built in log space (ln(estimate) ± 1.96 × SE) and only then exponentiated back to the ratio scale
  3. For a continuous outcome, standardized_mean_difference() computes Cohen's d from a pooled standard deviation, then a direct (non-log) confidence interval
  4. Every result is an EffectSizeResult that knows its own no-effect value (1.0 for ratios, 0.0 for differences) and can check crosses_no_effect() against it
  5. A zero cell — a real, common problem with small or rare-event studies — raises ZeroCellError unless continuity_correction=True applies the standard +0.5-per-cell fix

04The Code, Explained

def odds_ratio(a, b, c, d, continuity_correction=False):
    if 0 in (a, b, c, d):
        if not continuity_correction:
            raise ZeroCellError(...)
        a, b, c, d = a + 0.5, b + 0.5, c + 0.5, d + 0.5

    or_estimate = (a * d) / (b * c)
    se_ln = math.sqrt(1/a + 1/b + 1/c + 1/d)
    ln_or = math.log(or_estimate)
    return EffectSizeResult(
        measure="OR", estimate=or_estimate,
        ci_lower=math.exp(ln_or - Z_95 * se_ln),
        ci_upper=math.exp(ln_or + Z_95 * se_ln),
        no_effect_value=1.0,
    )

Every step traces directly to Prerequisite 6's explanation — this isn't a black-box statistics call, it's the textbook formula written out in five lines.

05Limits / What You Cannot Do Yet

Can't do yet

  • Support confidence levels other than 95% — Z_95 is a fixed constant, not computed for arbitrary levels
  • Pool multiple studies' effect sizes into one estimate — that's Module 17
  • Handle paired/matched-pairs data or adjusted (regression-based) effect sizes — only simple, unadjusted 2×2 tables and two-group continuous comparisons

Can do

  • Correctly compute all three standard effect-size families from raw study numbers, matching hand-computable textbook examples exactly
  • Build statistically valid confidence intervals, on the correct scale for each measure
  • Handle the real, common zero-cell problem explicitly, with the actual standard fix, not a crash

07Brain Exercise

The continuity-corrected zero-cell example produces OR = 60.294 with a huge confidence interval [3.195, 1137.854]. Is that number trustworthy?
The point estimate is real arithmetic, correctly computed — but a confidence interval that wide is itself the honest answer here, not a flaw in the calculation. A study with a literal zero-event cell has almost no statistical information about how large the true effect actually is; the continuity correction lets the formula produce a number instead of crashing, but it can't manufacture certainty the data never had. A CI spanning from about 3 to over 1000 is the formula honestly reporting "technically an effect, but we genuinely don't know how big" — which is more useful than either a crash or a falsely precise-looking number.

08There Are No Dumb Questions

Why does `crosses_no_effect()` compare against 1.0 for OR/RR but 0.0 for SMD?
Because "no effect" means something different on each scale — see Prerequisite 6. A ratio of exactly 1 means the two groups' odds or risk are identical; a difference of exactly 0 means the two groups' means are identical. Each `EffectSizeResult` carries the correct value for its own measure automatically, so a caller never has to remember which convention applies where.
What's the difference between `odds_ratio()`'s zero-cell handling and `risk_ratio()`'s?
Odds ratio needs all four cells (a, b, c, d) non-zero, since all four appear in its standard error formula. Risk ratio's formula only involves the two event counts (a and c) in a way that breaks at zero — the group totals (n1, n2) don't cause the same division problem — so only `a` and `c` are checked.
Could I use `standardized_mean_difference()` with unequal sample sizes?
Yes — the demo's own example uses n1=85, n2=90. The pooled standard deviation formula is specifically designed to weight each group's variance by its own sample size, so unequal group sizes are the normal case this formula is built for, not an edge case.
