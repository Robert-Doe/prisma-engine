01The Big Analogy

The technique's own name, taken literally Push a small snowball downhill and it picks up more snow as it rolls — it doesn't stay the size you started with. "Snowballing" a citation search works the same way, in two directions at once. Pull one paper off the shelf and flip to its bibliography: every work it cites is snow the ball picks up rolling backward through time. Then check a citation index for who has cited that paper since it was published: every one of those is snow picked up rolling forward.

backward_snowball() reads the seed paper's real reference list from Crossref. forward_snowball() reads who has really cited it since, from Semantic Scholar. Neither direction is simulated — both are live network calls against real citation graphs.

02What Happens, Step by Step

  1. fetch_crossref_record(seed_doi) gets the seed paper's own metadata, via Module 3's existing Crossref parser, unchanged
  2. backward_snowball() fetches the seed's reference list from Crossref, keeps only the references that carry a resolvable DOI, and resolves up to max_resolve of them into full Records
  3. forward_snowball() calls Semantic Scholar's citation graph API for papers citing the seed, parsing each into a Record via the new parse_semantic_scholar_paper()
  4. Module 5's merge_sources() — built two Tracks ago, unmodified since — combines the seed, backward results, and forward results into one corpus

04The Code, Explained

Backward snowballing's DOI-filtering step — real Crossref data, checked live, showed not every reference is resolvable:

references = resp.json()["message"].get("reference", [])
dois_with_metadata = [r["DOI"] for r in references if "DOI" in r]

resolved = []
for doi in dois_with_metadata[:max_resolve]:
    rec = fetch_crossref_record(doi)   # reuses Module 3's parser unchanged
    if rec is not None:
        rec.source_format = "CrossrefBackwardSnowball"
        resolved.append(rec)

05Limits / What You Cannot Do Yet

Can't do yet

  • Snowball recursively (expand from the newly-found papers too) — this module does exactly one hop in each direction
  • Resolve every reference — only DOI-bearing ones, and only up to max_resolve
  • Deduplicate the expanded corpus against the original search results — that's Module 6, not re-run here

Can do

  • Prove, with two real live citation-graph calls, that a corpus can grow beyond what any single search found
  • Distinguish backward-found (older, cited-by-seed) from forward-found (newer, citing-seed) work, provenance-tagged
  • Reuse two already-built modules (Module 3's parser, Module 5's merge) with zero modification

07Brain Exercise

The real backward results are from 2006-2017 and the real forward results are all 2026. Is that a coincidence?
No — it's structurally guaranteed, not coincidental. A paper can only cite work that already existed when it was written, so everything backward snowballing finds must be older than (or contemporary with) the 2018 seed. A paper can only be cited by work written after it existed, so everything forward snowballing finds must be newer. The direction of time is baked into which direction of snowballing can possibly find it — this is exactly why real systematic reviews run both: backward finds foundational work the original search might have missed, forward finds recent work that couldn't have been in a search run before it existed.

08There Are No Dumb Questions

Why not just recursively snowball from the newly-found papers too, to expand even further?
You could — and real systematic reviews sometimes do, across multiple rounds, until no new relevant papers turn up ("saturation"). This module deliberately does one hop, to keep the demo's live network cost bounded and the core mechanism clear; recursive snowballing is a straightforward extension of the same two functions, not a different technique.
What happens to references that don't have a DOI at all?
They're filtered out before resolution even starts — real Crossref data showed 28 of the seed's 60 references were "unstructured" free text with no DOI to look up. Those genuinely can't be resolved into full Records by this module; a real review would need to search for them by title/author manually.
Could backward and forward snowballing ever find the same paper?
Not from a single seed in one hop — a paper the seed cites was written before the seed, and a paper that cites the seed was written after it, so the same paper can't structurally be in both sets (see the Brain Exercise). It becomes possible once you snowball recursively across multiple papers, which is exactly when Module 6's deduplication engine would need to be run again.
