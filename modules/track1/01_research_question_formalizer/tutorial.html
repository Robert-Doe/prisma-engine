Prerequisites: PICO / PEO / SPIDER Frameworks

00Before You Start

You need the prerequisite above — everything in this module assumes you already know what a PICO/PEO/SPIDER slot is and why the framework choice matters. If that's new, read it first; it's five minutes.

01The Big Analogy

The intake clerk Walk into a busy clinic and describe your problem in your own words — a run-on story with no structure. A good intake clerk doesn't diagnose you. They listen for a few telling phrases ("it hurts more when I move," "I've felt this way for months") to guess which intake form fits — general medicine, a specialist referral, mental health — hand you that specific form, and then refuse to send you further into the building until every required box on it is filled in. They might even pre-fill one box themselves if your story made it obvious ("you said 'compared to how I felt in my last job' — is that the comparison box?"), but they never invent an answer for a box you haven't addressed.

formalizer.py is that clerk. suggest_framework_verbose() guesses which form (PICO/PEO/SPIDER) fits your question. FRAMEWORK_SLOTS is the fixed set of boxes on each form. validate() is the clerk refusing to let an incomplete form through.

02What Happens, Step by Step

  1. You give formalize() a raw question string, e.g. "Does remote work affect employee productivity compared to in-office work?"
  2. If you didn't specify a framework, suggest_framework_verbose() scans the text for SPIDER markers first, then PEO markers, and falls back to PICO if neither hits — returning both the guess and the reason, never a silent decision
  3. If the framework is PICO and you haven't already supplied a comparison slot, suggest_comparison() tries to split the sentence on "compared to" / "versus" / "vs." to extract one for you
  4. Your explicitly-given slots and any auto-suggested ones are merged into a ResearchQuestion object
  5. validate() checks every slot that framework requires is present and non-blank — if anything's missing, it raises MissingSlotsError naming exactly which fields, and construction stops there
  6. If validation passes, you get back a fully-formed, structured ResearchQuestion you can print, serialize to a dict, or pass to Module 2

04The Code, Explained

The framework-suggestion heuristic, in full — deliberately simple and auditable rather than a trained model:

def suggest_framework_verbose(question_text: str) -> tuple[Framework, str]:
    spider_hit = _first_match(question_text, _SPIDER_MARKERS)
    if spider_hit:
        return Framework.SPIDER, f'matched SPIDER marker "{spider_hit}"'

    peo_hit = _first_match(question_text, _PEO_MARKERS)
    if peo_hit:
        return Framework.PEO, f'matched PEO marker "{peo_hit}"'

    return Framework.PICO, "no SPIDER/PEO marker found — defaulting to PICO"

Every branch returns why, not just what — see DECISIONS.md for why that ordering (SPIDER → PEO → PICO-default) was chosen deliberately as the safer fallback.

Validation, which is where the "machine-checkable" promise actually gets enforced:

def validate(self) -> None:
    required = FRAMEWORK_SLOTS[self.framework]
    missing = [s for s in required if not self.slots.get(s, "").strip()]
    if missing:
        raise MissingSlotsError(self.framework, missing)

Notice this doesn't just return True/False — it names the exact missing fields in the exception, because "invalid" on its own isn't actionable; "missing: ['comparison', 'outcome']" is.

05Limits / What You Cannot Do Yet

Can't do yet

  • Turn a structured question into an actual boolean search string
  • Know whether the framework it suggested is genuinely the best fit — it's a starting suggestion, not a verdict
  • Handle any language other than English's common academic phrasings
  • Search anything — this module produces no network calls at all

Can do

  • Turn free text into a structured, framework-correct object
  • Catch and name incompleteness before it silently propagates downstream
  • Show you exactly why it suggested what it suggested

07Brain Exercise

Why does formalize() refuse to auto-suggest a value for any slot other than comparison — for example, why doesn't it try to guess population or outcome from the sentence too?
Comparison has a reliable textual signal in English academic writing — the word "compared to"/"versus" almost always precedes exactly the phrase you want. Population and outcome don't have an equally reliable syntactic marker; guessing them from raw text without one would mean silently inserting a guess that looks like real data but might be wrong, which is far more dangerous than leaving the slot blank and letting validate() catch it. A tool that fails loudly on a missing slot is safer than one that fails quietly with a wrong one.

08There Are No Dumb Questions

Isn't the framework-suggestion heuristic just... a list of if-statements? Is that really "proving" anything?
Yes, mechanically it is a short, ordered list of keyword checks — and that's exactly the point. The module's causal claim isn't "this AI understands your question," it's "a fuzzy question can be decomposed into structured, machine-checkable fields." A transparent, auditable heuristic proves that claim more honestly than a black-box model would, because you can see and verify exactly why each decision was made.
What happens if a question matches both a SPIDER marker and a PEO marker?
SPIDER wins — suggest_framework_verbose() checks SPIDER markers first and returns immediately on a hit, never reaching the PEO check. This is a real, inspectable consequence of the ordering decision explained in DECISIONS.md.
Why is MissingSlotsError a subclass of ValueError instead of its own standalone exception type?
So it plays nicely with any code that already catches ValueError for "the input I was given was invalid" — a very common Python convention. See DECISIONS.md for the full reasoning.
Can I add a new framework beyond PICO/PEO/SPIDER?
Yes — add an entry to FRAMEWORK_SLOTS with its required slot names, and update suggest_framework_verbose() if you want automatic suggestion for it. validate() and render_summary() both read from FRAMEWORK_SLOTS generically, so neither needs to change.

09What's Next
