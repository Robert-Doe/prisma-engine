00Before You Start

Finished Module 8 — this module is explicitly the second pass on whatever survived the first.

01The Big Analogy

The resume vs. the reference check A resume is written to look as strong as possible — that's not dishonest, it's just the nature of a one-page summary. A reference check calls former employers and asks specific questions the resume never had to answer: what was this person's actual role, how long did they really work there, would you hire them again. Plenty of resumes that look great on paper don't survive a real reference check — not because they lied, but because a summary necessarily leaves things out.

An abstract is the resume. Full text is the reference check. Neither of this module's two example exclusions involved a dishonest abstract — both papers' abstracts genuinely sound relevant. Reading further revealed a detail that changes the verdict.

02What Happens, Step by Step

  1. Each surviving record from Module 8 gets paired with its full text into a FullTextRecord
  2. screen_full_text() applies DEFAULT_RULES in order — population check first, then design check — exactly like Module 8's first-failure-wins logic
  3. population_is_knowledge_workers() fails if the full text mentions a disqualifying population term ("undergraduate," "university students") that the abstract never mentioned
  4. design_is_comparative() fails if the full text describes a purely qualitative interview design with no comparative/quantitative marker
  5. A record failing neither rule is genuinely included — confirmed by full text, not just by a promising-sounding abstract

04The Code, Explained

The rule that catches a design mismatch invisible in the abstract:

def design_is_comparative(item: FullTextRecord) -> bool:
    text = item.full_text.lower()
    qualitative_only_marker = "semi-structured interviews" in text
    comparative_marker = any(
        term in text for term in ("compared to", "measured output", "randomly assigned")
    )
    return not (qualitative_only_marker and not comparative_marker)

Notice the logic: this rule doesn't fail just because interviews are mentioned — plenty of legitimate comparative studies use interviews alongside quantitative measures. It only fails when interview language appears with no comparative marker anywhere, which is the actual signal of a qualitative-only design the abstract didn't disclose.

05Limits / What You Cannot Do Yet

Can't do yet

  • Fetch full text automatically — someone (a human, or a future module) has to supply it
  • Handle a PDF at all — plain text only
  • Detect nuance a keyword rule can't express (a design that's comparative but never uses any of the three marker phrases would incorrectly fail)

Can do

  • Prove, concretely, that a second full-text pass catches real disqualifications an abstract-only pass would miss
  • Log a specific, accurate reason tied to what full text actually revealed
  • Feed excluded_by_reason() straight into Module 7's tracker, same as Module 8

07Brain Exercise

This module's demo uses three invented records instead of real papers fetched live in Modules 4-5. Given how much this course values real, verified data, why make that call here specifically?
Because "real" and "honest" pointed in different directions for once. This course genuinely fetched real titles and abstracts from PubMed and arXiv in earlier modules — but it has no legitimate access to those real papers' actual full text. Attaching invented "full text" to a real paper's real title and real authors would make a false claim about what a specific, identifiable real paper actually says — arguably worse than using a clearly fictional example, which makes no claim about any real work at all. When "verify against real data" and "don't fabricate claims about real things" would conflict, this module chose not fabricating over superficial realism.

08There Are No Dumb Questions

Couldn't this module just re-run Module 8's rules against the full text too, instead of writing new ones?
Module 8's rules (abstract availability, publication year, a keyword check) already did their job at that stage. Full-text eligibility rules ask fundamentally different questions — ones that specifically couldn't be answered from an abstract, like confirming the actual study population or design. Re-running the same rules would just repeat the first pass, not add a second one.
What if the full text is in a different language, or is actually the wrong paper's text entirely?
This module has no way to detect that — it trusts that whatever string it's handed genuinely is that record's full text. That trust boundary is real and worth naming: a full-text retrieval step (out of this module's scope) is where that kind of error would need to be caught, before the text ever reaches this module's rules.
Is a keyword-based full-text rule actually reliable for a real review?
Not fully — the Limits section says so directly: a legitimately comparative study that never uses any of the three marker phrases would be wrongly excluded. Real full-text eligibility screening is usually done by a human reading the methods section, informed by criteria like these rules rather than replaced by them. This module demonstrates the logic and the value of a second pass, not a claim that keyword rules alone are sufficient for a real review.
