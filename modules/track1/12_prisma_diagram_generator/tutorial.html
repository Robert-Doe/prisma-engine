00Before You Start

Finished Module 7 and Module 8 — this module draws exactly what those two modules already tracked.

01The Big Analogy

The as-built drawing, not the original blueprint An architect's original blueprint shows what was planned. Real construction never goes exactly to plan — a wall moves six inches, a door gets relocated. After the building is finished, a surveyor produces an "as-built" drawing: redrawn from what's actually standing, not from what was originally sketched.

render_prisma_svg() is the as-built drawing. It doesn't draw a generic PRISMA template with blanks for you to fill in later — it reads Module 7's tracker, which only ever holds numbers real pipeline stages actually produced, and draws exactly that. This module's self-checks even prove it: the rendered SVG is parsed back open and checked for the literal real numbers ("n = 20", "n = 8") that came out of an actual run.

02What Happens, Step by Step

  1. render_prisma_svg(tracker) reads the tracker's identification, deduplication, screening, and (if logged) eligibility counts
  2. Each stage becomes a box; text wraps automatically and the box grows to fit it
  3. Exclusion counts (with their reasons) become side boxes, connected to the main flow by an arrow — reusing exactly the reason strings Modules 8/9 logged
  4. If eligibility hasn't been logged yet, the function stops after the screening stage — a valid, honest, partial diagram, not an error
  5. The result is a plain SVG string — save it with save_svg(), or embed it directly in any HTML page

04The Code, Explained

The core pattern — check whether a stage was logged, and only extend the diagram if it was:

if tracker.screening_included is not None:
    # ... draw the screened box, the excluded-at-screening side box ...
    if tracker.eligibility_included is not None:
        # ... draw the eligibility box, the excluded-at-eligibility side box,
        #     and finally the included box ...

And the self-check that proves the SVG actually reflects real numbers, not just that it's syntactically valid:

all_text = "".join(t.text or "" for t in root.iter("{http://www.w3.org/2000/svg}text"))
assert "n = 20" in all_text   # total identified
assert "n = 8" in all_text    # final included

05Limits / What You Cannot Do Yet

Can't do yet

  • Render the full PRISMA 2020 template exactly (registers vs. databases split, "reports sought/not retrieved" stage) — this is a simplified subset
  • Export to PNG/PDF directly — SVG only (any browser or vector tool converts it further)
  • Lay out more than a handful of exclusion reasons cleanly — very long reason lists would produce a tall, awkward side box

Can do

  • Turn real, validated tracker state into a real, parseable diagram artifact
  • Adapt automatically to however much of the pipeline has actually run
  • Produce output any web page can embed directly — this course's own tutorials, for one

07Brain Exercise

The demo's diagram stops after "Reports assessed for eligibility" instead of showing an "Included" box. Is that a bug?
No — it's the correct, honest behavior. Module 9 (the full-text eligibility engine) wasn't run as part of this module's demo pipeline, so tracker.eligibility_included is still None. Drawing an "Included" box anyway would mean inventing a final count that was never actually logged — exactly the kind of fabricated-looking-real output this course's quality bar rules out. A diagram that honestly stops where the real pipeline actually stopped is more trustworthy than one that always looks "finished."

08There Are No Dumb Questions

Why SVG text markup instead of, say, a PNG generated with a drawing library?
SVG is human-readable text — you can open this module's output in an editor and read the real numbers directly, diff two versions of it, or embed it inline in an HTML page with no separate image file to manage. A PNG would hide all of that behind opaque pixel data.
What happens if a reason string is extremely long — would it break the diagram?
It would render, but awkwardly — `_wrap_text()` will keep wrapping at its character limit regardless of length, producing a very tall side box. That's a real, named limit in this module's Limits section, not a silent failure.
Could I use this generator with a tracker I built by hand, not from a real pipeline run?
Yes — exactly what the self-checks do. `render_prisma_svg()` has no idea whether a tracker's numbers came from a live pipeline or were typed in by hand; it only ever reads whatever state the tracker actually holds.
