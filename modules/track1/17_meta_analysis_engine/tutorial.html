01The Big Analogy

Five clocks, and a question about why they disagree Five clocks each show a slightly different time. One theory: there's one true time, and each clock is just a little noisy — average them, trusting the steadiest clocks most, and you'll land close to the truth. That's the fixed-effect model's assumption: every study is estimating the exact same underlying effect, and any disagreement is just sampling noise.

A second theory: maybe the clocks are actually set to genuinely different times — not broken, just legitimately not synchronized. Averaging them still gives you useful information, but you should report your answer with much more uncertainty, because "the true time" might not even be a single number. That's the random-effects model: it allows each study to be estimating a genuinely different true effect, and it accounts for that extra between-study disagreement in its confidence interval.

This module's own demo has to decide which theory the five fictional studies support — and I² = 84.8% answers it: these clocks disagree too much to be explained by noise alone.

02What Happens, Step by Step

  1. from_effect_size_result() takes each study's Module 16 result and reconstructs its pooling-scale estimate and standard error — from the reported CI, the same way a real meta-analyst works from published numbers
  2. fixed_effect_meta_analysis() weights each study by 1/SE² (more precise studies count more) and combines them into one pooled estimate
  3. Cochran's Q and I² measure how much the studies actually disagree, beyond what sampling noise alone would explain
  4. random_effects_meta_analysis() uses Q to estimate τ² (between-study variance), then re-weights every study to account for it — widening the final confidence interval whenever real heterogeneity exists
  5. display_estimate() converts the pooled result back to its natural, readable scale (undoing the log transform for OR/RR)

04The Code, Explained

def fixed_effect_meta_analysis(effects):
    weights = [1 / e.se ** 2 for e in effects]
    pooled_y = sum(w * e.y for w, e in zip(weights, effects)) / sum(weights)
    pooled_se = math.sqrt(1 / sum(weights))

    q, df = _heterogeneity(effects, pooled_y)
    i2 = max(0.0, (q - df) / q * 100) if q > 0 else 0.0

And the line that makes random-effects genuinely different — every study's weight is inflated by the same shared tau2, which shrinks the influence of precise studies relative to imprecise ones once real disagreement is detected:

random_weights = [1 / (e.se ** 2 + tau2) for e in effects]

07Brain Exercise

The fixed-effect model says this pooled result is significant (CI entirely above 1); the random-effects model says it isn't (CI crosses 1). Which one is "right"?
Neither is simply wrong — they're answering slightly different questions, and which one is appropriate depends on whether the fixed-effect assumption (every study estimates the same true effect) is actually plausible here. With I² = 84.8%, that assumption is hard to defend — the studies disagree far more than sampling noise alone would predict. In real practice, high heterogeneity like this is usually a signal to report the random-effects result (or better, to investigate why the studies disagree — different populations? different outcome definitions? — before pooling them at all). Reporting only the fixed-effect model's tighter, "significant" interval here would be misleading given how much real disagreement exists between the studies.

08There Are No Dumb Questions

Why does `from_effect_size_result()` reconstruct the SE from a confidence interval instead of just using Module 16's original standard error directly?
Because `EffectSizeResult` (Module 16) doesn't store the SE directly — only the final estimate and CI bounds, which is what a real published paper typically reports too. Reconstructing SE from a CI is standard, common practice for exactly that reason: real meta-analyses very often only have access to a study's published estimate and interval, not its internal calculation.
What would `I²` be if all five studies had produced the exact same odds ratio?
0% — confirmed directly in this module's self-checks, which pool two identical studies and assert `I2 == 0.0`. Zero heterogeneity is what "the studies fully agree, beyond noise" looks like numerically.
Could I pool risk ratios and odds ratios together in one meta-analysis?
Not with this module as built — both happen to use the log scale, so `MixedScaleError` wouldn't catch it, but OR and RR aren't the same quantity even on the log scale, and pooling them together would still be statistically questionable. This module only actively guards against the more clear-cut error (mixing log-scale and linear-scale measures); mixing OR with RR is a real, subtler pitfall left to the caller's judgment.
