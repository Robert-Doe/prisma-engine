01The Big Analogy

The detective's cork board A detective pins photos to a cork board and connects them with red string — this suspect knows that one, that one was seen with a third. Some photos end up with string radiating out in every direction; those are the central figures. And sometimes two photos with no direct string between them are both connected to the same third photo — the detective circles that pattern, because two people connected to the same third party, even without knowing each other, are worth investigating together.

That's this module. CitationGraph is the cork board. in_degree() finds the photos with the most string pointing at them. find_co_citation_pairs() finds exactly that "not directly connected, but both connected to the same third paper" pattern — real co-citation, the bibliometric technique for finding related work without reading either paper's content.

02What Happens, Step by Step

  1. Module 13's backward_snowball() and forward_snowball() fetch the seed paper's real references and real citing papers, live
  2. Each result becomes an edge in a CitationGraph — (citing_doi, cited_doi) — with node identity kept consistent via Module 6's normalize_doi()
  3. A real second hop is fetched: the reference lists of the first two forward-citing papers, checked for overlap with the graph's existing nodes
  4. in_degree()/out_degree() compute real degree centrality directly from the edge set
  5. find_co_citation_pairs() groups edges by citing paper and reports every pair of papers cited together by the same citer

04The Code, Explained

def find_co_citation_pairs(graph):
    by_citer = {}
    for citing, cited in graph.edges:
        by_citer.setdefault(citing, set()).add(cited)

    pair_counts = {}
    for cited_set in by_citer.values():
        cited_list = sorted(cited_set)
        for i in range(len(cited_list)):
            for j in range(i + 1, len(cited_list)):
                pair = frozenset({cited_list[i], cited_list[j]})
                pair_counts[pair] = pair_counts.get(pair, 0) + 1
    return pair_counts

Grouping by citer first is what makes this real co-citation and not just "any two nodes in the graph" — a pair only counts if one real paper actually cited both.

05Limits / What You Cannot Do Yet

Can't do yet

  • Compute more sophisticated centrality (PageRank, betweenness) — only simple in/out degree
  • Cluster the graph into communities automatically — co-citation pairs are found, not grouped into clusters
  • Scale past a handful of hops — every additional hop is more live API calls, and this module fetches only 2

Can do

  • Build a real citation graph from two independent live sources and analyze it as data, not narrative
  • Find real, unplanned structural overlaps — proof the underlying corpus has hidden relationships a synthesis-focused reading would never surface
  • Reuse two prior modules' real functions (Module 6's normalization, Module 13's snowballing) unmodified

07Brain Exercise

The Hop 2 output shows one citing paper had "0 overlaps" and the other had a real one. What would it mean, methodologically, if this pattern held across many more citing papers?
If many of the seed's citing papers turned out to also cite "Directed Greybox Fuzzing," that would be real evidence those two papers are considered closely related work by the field itself — not because either paper says so, but because independent authors keep citing both together. That's the actual practical use of co-citation analysis in a real literature review: it can surface "these two papers belong in the same conversation" even when you'd have no reason to notice it just from reading either paper's abstract. One overlap out of two checked citing papers is a real but very small signal — the Limits section is explicit that this module's 2-hop graph is far too small to draw a confident conclusion from, only to demonstrate that the technique works.

08There Are No Dumb Questions

Why fetch references for only the first 2 forward-citing papers instead of all 5?
Cost, mirroring Module 13's own `max_resolve` reasoning — each additional paper checked is another live Crossref call. Two was enough to demonstrate the mechanism and, as it happened, to find a real overlap; a production tool doing this at scale would need to budget API calls much more carefully across potentially hundreds of papers.
Is in-degree alone a good measure of a paper's importance?
It's the simplest one, and it's what this module implements — but real bibliometrics also uses more sophisticated measures like PageRank (which weighs a citation from a highly-cited paper more than one from an obscure paper), explicitly named in the Limits section as not yet implemented here.
Could this graph include records from Module 5's live PubMed+arXiv search too, not just Module 13's snowball results?
Only for records that carry a real DOI Crossref or Semantic Scholar can look up — `CitationGraph`'s nodes are DOI-keyed. A PubMed record with a resolvable DOI could be added as another seed; an arXiv preprint without a DOI would need a different node-identity scheme entirely.
